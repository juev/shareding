# Sending links to linkding on Android

Status: R1–R23 and R25–R30 implemented with automated coverage on Android 9 and 16. R24 (queue editing rules) was removed on 2026-10-01 together with the queue editor and the "ShareDing…" form Share target; R23 and R29 now state what remains. R31–R33 (sync stopped by persistent errors, defaults applied at send time, Direct Share) and the Android 10 minimum were added on 2026-10-05 with automated coverage on Android 16; they changed R3, R8, R18, R19, and R28. WorkManager may delay recovery under Android power restrictions. A real VPN has not been tested manually.

Sources: the user's requirements on 2026-09-26 through 2026-10-05, including the decision to send titles from the Add Bookmark form and omit titles from Share and the 2026-10-01 decision to remove queue editing and the form Share target, the agreed RFCs, the iOS app in the sibling `share` repository, the observed Chrome share Intent on Android 16, and the [linkding API documentation](https://github.com/sissbruecker/linkding/blob/master/docs/src/content/docs/api.md).

## Purpose and scope

The app accepts a link from Android's Share menu or its add form, saves it on the device, and sends it to the configured linkding server. Saving does not depend on network availability or server settings. Android 10 (API 29) and newer are supported.

## Requirements

- R1. Register exactly one `text/plain` `ACTION_SEND` target, so Android does not group several ShareDing entries behind an extra choice. Accept HTTP(S) URLs and save each entry to the local database before making a network request. Keep the sending app visible through a transparent Share activity, show a short `Saved to queue` Toast only after a successful local write, and then finish. Show distinct feedback for invalid URLs, duplicates, or local save errors.
- R2. Send queued entries when a network becomes available. The server may be on a LAN or VPN without public internet access. `NET_CAPABILITY_VALIDATED` must not block such servers. Check linkding availability with an API request before sending.
- R3. Keep unsent entries after a timeout, HTTP error, connection error, or restart, and keep retrying without a fixed limit. WorkManager uses exponential backoff starting at 30 seconds; Android may run the work later. A successful `POST /api/bookmarks/` removes only the entry that was sent. Errors that retrying cannot fix stop sync instead (R31).
- R4. Let users add a URL manually with title, description, and tags. Fetch page details on request. Settings include the server URL, API token, default tags, unread/archive options, and Test Connection. Keep the connection result visible until the server URL or token changes. Test Connection checks the values typed in the fields without saving them; after a successful check of a server URL or token that differs from the saved one, Settings tells the user to save settings to sync with this connection. The queue shows status chips, Retry for failed entries, Sync now, the most recent attempt time and result, and an empty state with an Add bookmark action.
- R5. Keep the two Queue/Settings tabs, full-screen Add Bookmark form, icon, and brief Share confirmation from the iOS design. About shows the installed version and compact rows linking to the developer's website, the Android source repository, and the public privacy policy. Use native Android controls, Light/Dark themes, and screen reader labels.
- R6. Crashes, stopped background work, and reboots must not lose entries. Concurrent additions and manual sync must not remove an entry without confirmed delivery. Adding a duplicate URL must not change an entry while it is being sent.
- R7. Allow manual removal of one entry only after user confirmation. Canceling the confirmation keeps the entry and the existing worker. Confirming removal deletes the entry before replacing sync work.
- R8. Set `minSdk` to 29, the first Android version with sharing shortcuts (R33). Verify behavior on a current Android version.
- R9. Require `https://` for the linkding server URL before sending its API token through any distribution channel. Keep an existing `http://` server URL visible and editable; Test Connection and background sync must fail with a clear HTTPS requirement until it is changed. A queued bookmark remains available for later delivery. HTTPS uses normal certificate validation; redirects to another origin must not receive the token. HTTP(S) bookmark URLs and HTTP page metadata fetches remain supported without the linkding token.
- R10. Keep one visible Save settings action while editing any Settings section. After a successful save, hide the keyboard and show confirmation; on failure, keep the draft available for correction. Explain comma-separated tag entry with an example in Settings and Add Bookmark. When saved server credentials are available, fetch all pages of existing linkding tags and suggest matching names in both forms. Suggestions must not prevent entering a new tag or saving while the server is unreachable. Default tags are saved locally; Add Bookmark saves the entered tags with the queued bookmark.
- R11. The Add Bookmark metadata action appears after title, description, and tags. It fills empty fields from available HTML title, description, and keyword tags without overwriting text already entered. A failed fetch leaves the draft editable; a result for an outdated URL is ignored.
- R12. About presents the existing launcher icon with the app name and short description above its compact version and link rows.
- R13. Settings has no proxy options. After an upgrade from a version with proxy support, remove the saved proxy host, port, username, and encrypted proxy password once. Queued bookmarks, the server URL, the API token, and bookmark defaults stay unchanged.
- R14. Test Connection, tag suggestions, queued bookmark delivery, and Add Bookmark Fetch connect directly over the selected network and ignore any system HTTP proxy. An active system VPN carries these connections like other app traffic. Network selection, HTTPS certificate validation, and redirect/token protections apply to every request.
- R15. Repeated saves while sync is waiting must reuse that pending WorkManager job. If sync is running, schedule at most one successor so a link saved after its final queue read still gets processed. Automatic saves and recovery do not cancel in-flight delivery; manual actions follow R19.
- R16. Keep the title supplied in `EXTRA_TITLE` or `EXTRA_SUBJECT` locally for inspection, including multiline text. Drop a title that is only the shared link: any lone HTTP(S) URL, the link without scheme or `www.`, its prefix shortened with an ellipsis, or the link split by whitespace as in Mastodon timelines. Omit the title field from linkding requests for shared bookmarks; linkding determines its own title. Send a nonblank title saved in the Add Bookmark form, including details explicitly fetched into that form. Collapse whitespace into one line and limit the sent title to 512 Unicode code points without splitting surrogate pairs. Omit blank titles. Background sync does not fetch bookmarked pages. Explicitly entered descriptions are preserved.
- R17. Preserve Unicode text and encoded URLs from Android shares through local storage and the UTF-8 linkding JSON request. For fetched HTML, use the HTTP charset when supplied, otherwise detect a declared HTML charset and fall back to UTF-8. Do not decode or normalize URL escapes as text.
- R18. While sync can run (R31), register one persistent recovery check with a 30-minute WorkManager interval and a CONNECTED network constraint that accepts LAN and VPN networks without public internet validation. It reads the local queue and, only when links and server settings are present, restores a missing one-time sync request. It does not send links, replace pending or running work, append a successor, or shorten retry backoff. App startup and new-network callbacks also skip normal sync when the queue is empty or sync cannot run. When sync cannot run, the recovery check is cancelled; it is registered again when settings are saved or sync resumes. Android may delay the check to save power; no app screen or continuously running service is required.
- R19. Queue Sync now, Retry, saved connection settings, and confirmed deletion replace existing one-time sync work or create it if missing. Sync now, Retry, and saved settings also resume a stopped sync (R31); deletion does not. While sync cannot run, these actions cancel pending work and create none. Cancel active requests, reset retry delay, and read the current queue. Network constraints still apply. Before each POST, skip entries deleted since the batch was read. A request already accepted by linkding cannot be recalled.
- R20. Queue shows current running/waiting state and the most recent attempt's result and timestamp in small text, including when empty. Record failure time as well as success time. A successful later item in a partly failed batch must not clear the failure. Settings has no Sync section.
- R21. Tapping a queue card expands or collapses its details. Expanded title, URL, and error text wrap without ellipsis and support selection and copying. Separate Delete and Retry controls keep their existing actions.
- R22. HTTP errors keep their status code and the server's explanation in the queued entry, the latest sync error, and the Test Connection result. The first line names the error: `linkding rejected the API token (HTTP 401)` for 401 and 403, `linkding API not found (HTTP 404)`, otherwise `linkding returned HTTP <code>`. A JSON body follows as text, not as JSON: `detail` and `non_field_errors` as they are, field errors as `field: message`. A plain-text body is kept unchanged; an empty response shows only the first line.
- R23. Queued entries cannot be edited. An expanded card shows details and offers only Retry for a failed entry and Delete. Nothing in the app pauses sync.
- R25. Before a URL enters the queue from Share or Add Bookmark, remove known tracking query parameters: names starting with `utm_`, common click identifiers such as `fbclid`, `gclid`, `yclid`, and `msclkid`, and `si` on YouTube and Spotify hosts. Keep every other parameter, their order and encoding, and the fragment. Drop `?` when no parameter remains. A URL without tracking parameters is stored unchanged, and cleanup runs before the duplicate check.
- R26. Before sending a queued bookmark, the sync worker resolves links on a fixed list of URL shorteners (`t.co`, `bit.ly`, `vk.cc`, `clck.ru`, and similar). It sends GET requests without the linkding token and without following redirects, reads `Location` from a 3xx response, and repeats while the target is still a listed shortener, up to five requests. The first host outside the list ends resolution; that site is never contacted. The resolved URL gets R25 cleanup and replaces the URL in the linkding request, and `Original URL: <short link>` is appended to the notes. Any failure (timeout of about five seconds per request, network error, non-redirect response, invalid `Location`, too many hops) sends the original URL unchanged and does not by itself fail delivery. The queued entry keeps the short URL.
- R27. The Add Bookmark URL field has a paste button. It reads the clipboard only when tapped and replaces the field with the first HTTP(S) link found in the clipboard text, extracted and cleaned as in Share. Without a link, it shows a short message and leaves the field unchanged.
- R28. Sync errors that retrying cannot fix (HTTP 401/403, 404, the HTTPS requirement, an unreadable token) show one notification per error kind until the kind changes or a sync succeeds. Its title names the problem and its text says that saved links stay in the queue and what to change in Settings; the server response is not repeated there. If the oldest queued link is older than 24 hours while server settings are present, show one "waiting" notification for that link. Tapping a notification opens the app; a successful sync or an empty queue removes them. Transient errors do not notify. Saving a link while sync cannot run (R31) shows the notification for the current reason again, even after the user dismissed it, and adds the reason to the save confirmation: `Saved to queue · linkding is not set up` or `Saved to queue · sync is stopped`. Saving settings removes the notification. On Android 13+, request the notification permission once, the first time the main screen opens. The app has no notification setting of its own: after that the user turns alerts on or off in the system settings. Without the permission or with notifications turned off, sync behaves the same and errors stay visible in Queue.
- R29. Leaving the Add Bookmark form with a changed draft asks for confirmation; an unchanged draft closes directly.
- R30. Every interactive control has a name a screen reader can announce. A setting switch and its label form one toggleable element, so the label is read with the state and a tap anywhere on the row toggles it. On screens wider than 640 dp the queue, both forms, Settings, and the Save buttons keep a 640 dp width and stay centred; narrower screens use the full width.
- R31. Sync can run only when the server URL and API token are set and no persistent error has stopped it. A persistent error is HTTP 401/403, HTTP 404, the HTTPS requirement, or an unreadable token, from the server check or from a POST. The worker marks the affected entry failed (after a failed server check, up to the first 50 entries), keeps later entries pending, records the reason, and finishes without a retry. The reason survives a restart. While sync cannot run, Share, Add Bookmark, deletion, app startup, and new networks create no WorkManager work, and the Queue status line shows `Set up linkding in Settings to sync` or `Sync stopped ·` with the problem. Sync resumes only through Sync now, Retry, or saved settings; a successful sync clears the reason.
- R32. Default tags, unread, and archive are read from the current settings for every POST, so a change applies to all queued links, including links saved before the server was set up or while sync was stopped. A queued entry stores only the tags entered for it in Add Bookmark; they are sent after the default tags without duplicates.
- R33. Publish one long-lived sharing shortcut for `text/plain`, so ShareDing appears in the Direct Share row. Publish it on app start and again after each share. Selecting it saves the link exactly as the R1 target does. The shortcut also appears in the launcher menu of the app icon and opens the app there: Android does not keep a shortcut that is excluded from the launcher as a dynamic one.

## Invariants and compatibility

- A local write happens before background work is scheduled or a network request is made.
- Automatic removal happens only after confirmed API success. Manual removal is a separate user action.
- Delivery has at-least-once semantics. If the server accepts a POST but the response is lost, the request may be repeated. Current linkding updates an existing bookmark with the same URL.
- Missing server URL or token does not prevent local saving. The queue remains available for delivery after setup.
- A saved page URL may use HTTP or HTTPS regardless of the linkding server URL scheme.
- Bookmark defaults belong to settings, not to queued entries (R32). Loading tag suggestions does not change queued bookmarks. A missing connection does not prevent local tag entry or saving bookmark defaults.
- The app has no proxy transport. Proxy support was removed because HTTP proxy Basic credentials could only be sent without TLS; a system VPN is the supported way to reach a server through another route.
- Room version 2 adds a `sendTitle` flag. Version 1 entries retain every existing field, with `sendTitle = false` because their title source was not recorded. Their titles stay visible locally; linkding extracts the title on delivery. New nonblank form titles set the flag; Share titles do not.
- Room version 3 drops the `unread` and `archived` columns. Every other field of a queued entry is kept. Entries queued before the upgrade keep the default tags stored with them and take both flags from the current settings.

## Design decisions

Kotlin and Jetpack Compose provide the Android UI; Room stores the queue; WorkManager runs durable background sync with a network constraint and retries. Its `NetworkRequest` requires the `INTERNET` capability, but not `VALIDATED` or `NOT_VPN`: Wi-Fi without public internet validation and VPN remain candidates. The worker reads Room entries in creation order, tries available networks, and checks linkding through `GET /api/tags/`. The API token is stored separately from the queue using Android Keystore protection. Android Network Security Config allows HTTP for bookmark page fetches; the app sends the token only to the configured HTTPS linkding origin.

App startup and new-network callbacks check the queue before ensuring one normal sync job exists. Sharing and form saves reuse an enqueued or blocked job. If only a running job remains, they add one successor; if no job remains, they schedule a new one. Manual queue actions instead use WorkManager REPLACE. Scheduling waits for WorkManager to persist the request. OkHttp calls propagate coroutine cancellation to the socket, including while reading response bodies. The worker's database update before POST returns the number of matching rows; a deleted entry is skipped.

The separate periodic recovery worker starts after an initial 30-minute delay and repeats at a 30-minute WorkManager interval while its network constraint is met. It only checks Room and server settings, then uses KEEP to restore an absent normal sync request. Existing pending retries and running uploads remain untouched. WorkManager can launch the app process for this check after ordinary process death or reboot; Android can delay it, and a user force-stop prevents background work until user interaction.

For R10, the Settings Save action applies to the current form draft and remains visible below the scrollable sections. Tag suggestions use the saved server URL and token, follow the existing LAN/VPN network selection behavior, and request each page from the configured origin. An unavailable tag list leaves free-text entry usable.

For R11 and R12, HTML metadata fills the visible bookmark draft.

For R16–R17, Share titles serve as local labels. A persisted flag distinguishes accepted form titles from shared or legacy titles, without guessing which line of a multiline preview is the actual title. The URL remains encoded as received; HTML explicitly fetched into the form is decoded before parsing, while Intent strings and the API request remain Unicode text.

## Verification scenarios

- R1, R2: Share a URL without a network or server settings. ShareDing appears once in the text Share menu, keeps the sending app visible, saves the entry, shows a short Toast, and sends it after network access and server settings become available. Sharing invalid text leaves the queue unchanged.
- R3, R6: Return 401/5xx from the API, drop the connection, or stop the worker. The entry remains queued and is removed only after a successful POST. A new link during backoff waits for the existing retry.
- R15: Save 50 links while sync is waiting for a network: one unfinished request remains. Save links while sync is running: one successor remains blocked without canceling the running job. After it finishes, the successor processes any link it missed.
- R18: With an empty queue or missing server settings, run recovery and observe no new sync request. With a queued link and no sync request, recovery adds exactly one. With an enqueued retry or running upload, recovery keeps its WorkManager ID and adds no successor. Repeated registration keeps one periodic request. After an ordinary process kill or reboot, WorkManager can run the saved work without reopening the UI.
- R2, R9: Reach an HTTPS linkding server through LAN/VPN without public internet validation. Load an existing HTTP server setting and verify that Test Connection and background sync show the HTTPS requirement, send no token or queued bookmark, and preserve the queue until the URL is corrected. HTTP bookmark URLs and page metadata fetches remain available.
- R4, R5: The add form, Queue, and Settings perform their actions and show the agreed states in Light/Dark themes. Test an unsaved token and confirm the save reminder appears and goes away after saving; covered by `QueueUiTest.testedButUnsavedTokenAsksToSaveSettings`.
- R7, R19: Cancel removal and keep the entry and worker; confirm removal and replace work after deleting only the selected entry. Remove a later batch entry during an earlier POST and verify the removed URL is never sent. Delete an entry whose upload is awaiting a response and verify remaining entries send before the old request timeout. Covered by `QueueSyncInteractionTest`, `SyncSchedulerTest`, and `QueueUiTest`.
- R10: Enter default tags, save from the bottom of Settings, and verify persistence and keyboard dismissal. Type a partial tag name and select a server suggestion in either form; verify comma-separated names and local saving. Return an API error or disconnect the server and verify that manual tag entry and saving still work.
- R11: Fetch an HTML page containing title, description, and keywords. Confirm all available fields appear and can be edited before saving. Omitted metadata and a failed request do not clear manual values.
- R5, R12: Open About and confirm the app icon and identity appear above version and links, including the public privacy policy.
- R13, R14: Upgrade from a build with a saved proxy and credentials; confirm the proxy values and encrypted password are gone while the queue, server URL, token, and defaults remain. Confirm Settings shows no proxy options and that sync and page fetches reach their origins directly. Covered by `SettingsStoreProxyCleanupTest`, `QueueUiTest`, and `SyncWorkerTest`.
- R16, R17: Share a multiline non-ASCII title and verify it remains local while the POST omits title and no page request occurs. Save a form title, then confirm it is sent as one line with at most 512 Unicode code points. Share a title equal to the link and the link split by whitespace and verify that no title is stored. Verify the same behavior after retries and a version 1 database upgrade. Covered by `ShareIntentTest`, `SyncWorkerTest`, `LinkdingApiTest`, `BookmarkTitlesTest`, and `BookmarkMigrationTest`. Explicit HTML fetch tests retain charset coverage in `PageMetadataTest`.
- R20–R22: Expand a long title, URL, and error, verify none is ellipsized, and collapse again. Return a structured HTTP error, show its details as text and keep the attempt time, then manually sync successfully and show that result with an empty queue. Settings has no Sync Now action. Covered by `QueueUiTest`, `ApiErrorsTest`, `LinkdingApiTest`, and `SyncWorkerTest`.
- R23: Expand a failed queue card and confirm it offers Retry and Delete and no Edit. Covered by `QueueUiTest.cardExpandsFullSelectableTitleUrlAndErrorThenCollapses`.
- R25: Share and add URLs with tracking parameters, host-specific `si`, encoded names, and URLs without tracking parameters; confirm the stored URL. Covered by `TrackingParamsTest`, `UrlsTest`, and `ShareIntentTest`.
- R26: Resolve a single redirect, a chain of shorteners, and failures (timeout, disconnect, 200 page, redirect without or with invalid `Location`, six hops); confirm the request carries no token and only listed hosts are contacted. Covered by `ShortLinkResolverTest` and `SyncWorkerTest.workerSendsResolvedShortLinkAndKeepsOriginalInNotes`.
- R27: Paste text containing a tracked link and text without a link. Covered by `QueueUiTest.pasteButtonFillsUrlFromClipboard` and `QueueUiTest.pasteWithoutLinkKeepsUrlField`.
- R28: Classify errors, show and deduplicate problem and waiting notifications, and clear them after success. On Android 13+ a fresh install shows the permission dialog on first launch and, after a denial, not again; Settings has no notification row. A rejected token shows the instruction, not the server response. Covered by `SyncProblemTest`, `NotificationAccessTest`, `SyncNotifierTest`, and `QueueUiTest.settingsHaveNoNotificationRow`; the denial flow was checked manually on API 36.
- R1, R29: Confirm the package exposes one Share target labelled ShareDing; leave the Add Bookmark form with a typed link and confirm the discard prompt. Covered by `ShareIntentTest.appearsInTextShareTargets` and `QueueUiTest.addFormAsksBeforeDiscardingTypedLink`.
- R30: Find "Mark unread" and "Archive" in Settings as switches and toggle one by its label; covered by `QueueUiTest.bookmarkDefaultSwitchesAreLabelledAndToggleFromTheirRow`. The width limit was checked on an API 36 emulator set to a 1280 × 800 dp landscape display and to the default phone size; it has no automated test.
- R31: Share and save without server settings, then after a 401: the link is stored, no sync or recovery work exists, and the notification names the reason. Return 401 from the server check and 403 from a POST: the worker succeeds without a retry, a second run sends nothing, and Sync now delivers the queue once the server accepts the token. Covered by `SyncSchedulerTest`, `SyncRecoveryTest`, `SyncWorkerTest`, `SyncNotifierTest`, `ShareIntentTest`, `SyncProblemTest`, and `QueueUiTest`.
- R32: Queue a shared link and a form link with its own tags, change the defaults, and confirm the POST bodies carry the new tags and flags; repeat for a link stuck on a rejected token. Upgrade version 1 and version 2 databases and confirm the queue is intact and the two columns are gone. Covered by `SyncWorkerTest`, `LinkdingApiTest`, `QueueUiTest`, and `BookmarkMigrationTest`.
- R33: After app start the dynamic shortcut carries the share-target category; covered by `ShareIntentTest.appStartPublishesDirectShareTarget`. On an API 36 emulator the system share sheet showed ShareDing in the Direct Share row and selecting it queued the link; this was checked manually.

Automated checks: `./gradlew assembleDebug assembleRelease testDebugUnitTest testReleaseUnitTest lintDebug lintRelease connectedDebugAndroidTest`. URL, metadata, and linkding API cases are covered in `app/src/test/java/org/evsyukov/shareding/network/`; Room queue, Share Intent, worker, scheduler, and UI cases are covered in `app/src/androidTest/java/org/evsyukov/shareding/`.

Manual network checks: Turn off Wi-Fi and mobile data, share a URL, close the app, turn Wi-Fi on, then confirm the POST reaches a test server and the queue empties. To check LAN access without public internet, disable public internet validation in the emulator, confirm that `NET_CAPABILITY_VALIDATED` is absent, and send to a reachable linkding server. To check backoff, make the test server return 503 for the first POST and 201 for the next; the entry must remain queued until the second response.
